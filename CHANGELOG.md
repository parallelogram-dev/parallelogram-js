## [0.7.15] - 2026-09-19

### Fixed

- A dropdown menu's items no longer keep a focus ring when the pointer opened the menu. The rule that hides rings from pointer users named the trigger, and a menu is not inside it; it now names the menu too. Keyboard users still see where they are.

## [0.7.14] - 2026-09-19

### Added

- Dropdown, an enhancement: a menu that opens beside its button. It is Toggle with a place to sit and a menu to keep -- every Toggle attribute applies under the `data-dropdown-` prefix, with a menu's defaults: outside clicks close it, and every dropdown on the page shares one group unless given its own, so opening one closes the rest. The menu is on the page, named by `data-dropdown-target`, or built the first time the trigger opens from a `<template>` named by `data-dropdown-template`, with every `{name}` in its text and attribute values filled from the trigger's `data-dropdown-param-<name>` attributes -- as text, never parsed as markup -- and removed when it closes unless `data-dropdown-keep`; a page with a menu per row keeps one template and a few attributes per row. `data-dropdown-placement` picks a side and an alignment, the menu flips when there is no room, stays inside the viewport and follows the trigger while the page scrolls; `data-dropdown-match-width` and `data-dropdown-portal` do what they say. Rows need not be alike: a boolean attribute filled from a param, `disabled="{locked}"`, is its presence, and `data-dropdown-disabled` and `data-dropdown-hidden` on a trigger name items by their `data-dropdown-item` to disable or leave out; `data-dropdown-params` carries every param in one attribute, as JSON or as `{id: 12, name: Ada}`. The menu is drawn on the dropdown surface `<p-select>`'s list uses, each item a row with a hover and a checked mark, so a menu of plain buttons and links looks like a menu; an icon before a label sits in line, and a disabled item, `disabled` or `aria-disabled="true"`, is a dimmed row the arrow keys pass over and a press leaves alone. The arrow keys move between items, a letter jumps, Escape closes back to the button, and choosing an item dispatches `dropdown:select` with the item and the trigger's params, then closes unless the item or the menu carries `data-dropdown-stay`. `Dropdown.enhanceAll()` mounts it without the framework.

### Changed

- Toggle is built to be extended: it resolves its target through three seams a subclass can take over -- `_resolveTarget`, `_attachTarget` and `_detachTarget` -- and calls `_ensureTarget` before opening, so a subclass that sets `defersTarget` can build a target on first show. Its event names and the attributes it remembers come from the class rather than literals, and `data-toggle-enhanced`, written on every trigger, is in its contract.

### Fixed

- `p-uploader`: Replace sits in the pill beside Edit and Delete rather than as an underlined link in the toolbar next to it, so a single-file card shows one segmented control instead of a link beside an icon button. It keeps `replaceLabel` as its name and tooltip, and still uploads the new file before deleting the old one. The toolbar now holds only Move up and Move down, and is left out of the card when neither is allowed. Every button carries a `part` a page can style without forking the component: `edit-button`, `replace-button`, `delete-button`, `move-up-button`, `move-down-button`, `cancel-button`, `confirm-button` and `save-button`. Closes #68.
- `p-uploader`: a replacement no longer stacks a second card in front of the file it replaces. The outgoing card steps out of the layout as soon as the new one takes its place, so one card stays where it was and shows the upload, instead of the list growing and then shrinking. The original comes back if the upload fails or if the server refuses to delete it.
- `p-uploader`: a file's fields are listed without a gap between the rows, which already carry their own height, so they read as one list rather than a spread one. `--uploader-field-gap` still sets one.
- `p-uploader`: the filename is set a step below the fields it labels, in the body weight rather than bold, so it labels the card instead of shouting over the values beside it.
- The documentation site's stand-in upload server no longer calls `crypto.randomUUID()`, which is undefined outside a secure context, so the examples work when the site is read over plain HTTP from another machine.

## [0.7.13] - 2026-09-18

### Added

- `data-form-enhancer-message-class` names the class FormEnhancer puts on a message element it creates for a field, when the form has no `data-error-for` element of its own; several classes separated by spaces are all added. A site whose stylesheet already styles its server-side errors can name that class instead of styling the framework's.

### Changed

- **Breaking:** the message element FormEnhancer creates carries `form__error` rather than `form-enhancer__error`: it is an element of the form, in the `form` block the package's own form styles use, not of the enhancer. A stylesheet that styles `.form-enhancer__error` either renames the selector or sets `data-form-enhancer-message-class="form-enhancer__error"` on the form.

## [0.7.12] - 2026-09-17

### Added

- Tooltip, an enhancement: `data-tooltip="…"` on a control shows the text beside it after a short delay under the pointer and at once on keyboard focus, and `data-tooltip-target` names an element whose content is the description when the text is empty. It goes when the pointer leaves, focus moves, the control is pressed or Escape is pressed, and links to the control with `aria-describedby` while shown -- a description, not a name, so a control with only an icon still needs its own `aria-label`. `data-tooltip-placement` picks a side and the tooltip flips when there is no room, staying inside the viewport with the triangle still pointing at the control; `data-tooltip-arrow="false"` drops the triangle. It fades and moves into place over the framework's transition, and appears at once for a visitor who prefers reduced motion. Touch gets nothing. Ten custom properties from `--tooltip-bg` to `--tooltip-transition-duration`, and `Tooltip.enhanceAll()` mounts it without the framework.

## [0.7.11] - 2026-09-17

### Changed

- The light theme's solid colours clear 4.5:1 under their text. The accent is `#2563eb`, which was its hover, with `#1d4ed8` as the hover; it was `#3b82f6`, 3.7:1 under white and the same ratio as link text on a white page, which fails for body text outright. Success is `#15803d`, was `#16a34a` at 3.3:1. Warning keeps its orange -- brighter, `#f97316` -- and carries dark text, `#431407`, at 5.3:1, because every orange that reads under white is a brown. Danger was already 4.8:1 and is unchanged, as is the whole dark theme. The status contrast test holds every pairing to 4.5:1 now rather than 3:1 for a solid.
- The documentation's examples show the library's button classes as a page would define them. The examples have always used `btn`, `btn--primary` and `btn--danger`, and the docs never defined them, so a primary or a danger button looked like every other button, and `<p-modal>`'s own `::slotted(.btn--primary)` rule could not help: a rule from the page beats a component's slotted rule whatever its specificity. The example stage defines `btn` and its `--primary`, `--secondary`, `--danger`, `--ghost`, `--brand`, `--sm` and `--lg` variants with the design system's button mixins, which is what Getting started tells a page to do, and a plain button in an example is the same secondary button rather than a hand-written docs style of a different height and type.
- A status toast is the status colour behind its contrast text -- the same `--color-success`, `--color-warning` and `--color-danger` a page paints its own status with -- rather than the deeper `-strong` shade under white, which sat beside the solids as a third set of colours. `--toast-bg-success`, `-warning` and `-error` default to the status colours accordingly; `--toast-text-color` still overrides every toast's text. The `-strong` tokens and `--color-on-status` stay declared for a page that wants the deeper tone, and nothing in the library reads them now.
- Every hover in the library eases over `--framework-transition-duration`, 0.2s, and none of them does for a visitor who prefers reduced motion. Buttons built on the design system's `button-base` eased everything over a literal 0.15s, and an accordion's summary switched hard; `button-base` eases its background, text and border over the framework token now, and the `transition` mixin takes a list of properties and eases each alike, inside the media query that respects the preference. `<p-select>` and `<p-uploader>`'s drop zone eased on literal durations with no reduced-motion rule, and have one; `--framework-transition-duration` itself is `0s` under the preference, so everything reading it -- focus outlines included -- follows. `<p-datetime>`'s quick dates ease over the picker's own 0.15s. The documentation's example buttons ease the same way.
- `<p-datetime>`'s quick dates are pills on the muted surface in the text colour, and the accent with its contrast text under the pointer. They were ghost buttons -- transparent, muted text -- with a hover that painted the strong accent under the panel's background colour, and a second hover rule that applied on touch screens too. The four `--datetime-preset-*` properties follow `--color-surface-muted`, `--color-text`, `--color-accent` and `--color-accent-contrast`; `--datetime-preset-hover-color` is new.

### Fixed

- When a toast is dismissed, the toasts below it float up to their new place over the toast animation's duration rather than jumping there in the frame its space closes; a new toast that pushes others along floats them the same way. Nothing floats for a visitor who prefers reduced motion.

## [0.7.10] - 2026-09-17

### Added

- `--color-success-contrast`, `--color-success-text`, `--color-warning-contrast` and `--color-warning-text`, so every status colour has the five roles danger had: the solid, the text on it, the strong, the tint a message sits on, and the text on that tint. Success and warning had no `-contrast`, so text on their solids fell back to `--color-on-status`, white in both themes -- readable on the light theme's solids and 1.7:1 on the dark theme's light green -- and no `-text`, so a message on their tint had nothing to be but the dark `-strong`, 1.8:1 over a dark surface. A browser test now holds every status pairing in both themes: 3:1 on a solid, which is a button or a badge, and 4.5:1 for a message on a tint or a strong.

### Fixed

- The documentation site's example stage was `#fff` with dark text and `color-scheme: light` whatever the theme, so in the dark theme every component sat on a white patch: the accordion's light text over it at 1.2:1, DataTable's inherited dark text on its own dark cells at 1.1:1, and native inputs and buttons painted light. The stage takes its ground, text and border from the design system now, and its plain buttons and fields from the secondary-button and control tokens, so an example sits on what a page using the library would give it, in either theme. A scan of every component page in the dark theme went from 48 flagged elements to one, which is the accent button and correct.
- On the design system page, a status tint's sample carries the status's `-text` rather than its `-strong`, the `--color-on-status` sample sits on a `-strong` as toasts do rather than on the solid, and a family with no colour of its own no longer offers a length as a background, which painted white text on the page ground. In the dark theme no sample is under 4.5:1 now; in the light theme the accent, success and warning solids with white text sit at 3.3 to 3.7:1, which is the palette as drawn.

## [0.7.9] - 2026-09-17

### Changed

- **Breaking:** the third brand colour is spelled `--brand-complementary`, with `--color-complementary`, `-hover` and `-contrast` to match. It shipped a day ago as `complimentary`, which means free of charge; a colour that completes another is complementary. A page that set the old name sets the new one; nothing else moves.
- The documentation site hosts its monospace face, IBM Plex Mono, beside its text face rather than loading it from Google Fonts: two fewer origins to connect to and one fewer stylesheet to wait for before code is readable, for 20 kB of font files the site serves itself.
- The README said a patch release never includes a breaking change, and 0.7.7 and 0.7.8 did. It says what is true now: before 1.0 any release may, each is marked **Breaking** with what to change, and an upgrade guide carries the same list -- _Upgrading within 0.7_ is that guide for 0.7.7, 0.7.8 and this release, which the old line also promised and no release since 0.6 had.
- The design system page counts a token another token follows as read, and says by which: the dropdown border reads `--surface-panel-border-width`, and `--button-brand-bg` reads `--color-secondary`, and the page called both unread because only component stylesheets were counted. Six tokens were mislabelled that way, and a seventh, `--surface-dropdown-item-current-bg`, was called unread because `<p-select>` reads it through a `var()` a formatter had wrapped onto two lines and the search wanted them on one; it counts either now.
- The documentation site loads in one wave rather than three. Every page shipped the full text of every contract -- descriptions, examples, custom properties, 37 kB gzipped -- as JavaScript, because the runtime read three fields from them to know which module to load for which tag; it reads those fields from a module generated at build time now, and the contracts stay on the build side. Each page also discovered its chunks one dynamic import at a time, three round trips deep; each page now preloads the chunks its own markup will need, and the framework's core, which every page loads, is one chunk named for what it is. On the p-datetime page that is 21 requests to 12 and 82 kB of script to 47. During development a save reloads only the pages it made stale instead of every open page, `npm run site:lan` serves the built site to another device on the network at a tenth of the dev server's weight, and the core modules are compiled before the first request.

### Removed

- Fourteen declared tokens nothing read and no token followed: `--surface-control-shadow`, `--surface-button-shadow`, `--surface-dropdown-color-text`, four of the `--surface-item-*` family (its border colour and text colour stay, read by Accordion), five of the `--surface-touch-*` family (its radius, border width and shadow stay, read by the uploader), `--surface-card-border-color` and `--panel-color`. Setting any of them changed nothing, so removing them changes nothing. `--color-success-tint` and `--color-warning-tint` stay although no component reads them yet: they are the message ground a page's own status messages sit on, the same role `--color-danger-tint` plays for the uploader.

## [0.7.8] - 2026-09-17

### Added

- The package ships one file with everything in it, `dist/parallelogram.js`, which `unpkg` and `jsdelivr` now point at. A page loading the library straight from a CDN gets it in one request instead of discovering each module from the one before it. It carries every component whether the page uses one or not, about 74 kB over the wire, so the individual files remain the better choice behind a bundler or for a page using one or two components -- Getting started now says which to reach for and why.
- Every string an element shows can be translated, in two places: once for a site, on the class -- `PModal.defaults.closeLabel = 'Fermer'` -- and for one instance with an attribute, `close-label="Fermer"`, which wins. Enhancements work the same way through `defaults` and their `data-*` options; the elements never had a class default, so every one of their strings was fixed at English. Text with `{name}` placeholders keeps the sentence's own word order. Covered: `<p-modal>`'s close button; `<p-select>`'s placeholder, clear button, search hints and empty-list message; `<p-toasts>`' dismiss button; Lightbox's viewer, close, previous and next names and its two load-failure messages, one naming the image from the thumbnail's alt text and one for a thumbnail without any; SelectLoader's load-failure message and retry button; and all 33 of `<p-datetime>`'s, from its placeholders and button names to its range hints, quick dates and validity messages. Its three mode nouns feed nine sentences through `{what}`, so a page that sets `date-noun="fecha"` has "Elige fecha" wherever the picker names what is being chosen, and the field's fallback label is the same noun with its first letter uppercased in the page's language rather than a second word to translate. Its placeholders read "Select date and time..." where they read "date & time", so that one noun serves. And all 29 of `<p-uploader>`'s, from the drop zone and every button on a file card to the messages for a refused file, a failed save and a failed reorder. A card reads its words from the uploader it is in, so a page sets them once on `<p-uploader>`; `PUploader.defaults` and `PUploaderFile.defaults` are one object, so a card on its own has the same words. Each control on a card had a tooltip and an accessible name that disagreed -- "Save" and "Save details" -- and has one label for both now, the longer one. Each is listed under _Attributes_ on its page. No translation ships, on purpose: one that could not be checked would look finished and be wrong, and dates, times and month names already come from the browser in every language. Getting started has a section on it.
- A page can set a second and a third brand colour, `--brand-secondary` and `--brand-complimentary`, the way it can already set `--brand-primary`, each with a hover and a contrast beside it. They feed two roles a component can read, `--color-secondary` and `--color-complimentary`, and until a page sets one both are the accent, so a page that leaves them alone looks exactly as it did. Nothing in the library reads them on its own: a `button-brand` mixin sits beside the `button-primary`, `button-secondary`, `button-danger` and `button-ghost` mixins for a page that wants a button in its own colour. `--button-secondary-*` is untouched and still the quiet outline it has always been -- it was never a second brand colour, which is the confusion these roles settle.
- `<p-select>` documents the seven custom properties its own stylesheet reads and its contract had never listed: the control background, border, border width and radius, padding, placeholder colour, and the outline drawn while the list is open. DataTable documents `--datatable-error-default`.

### Changed

- `<p-datetime>` formats dates, times, month and weekday names in the language of the nearest `lang`, where it formatted them in the browser's whatever the page said. A French page in an English browser showed English month names. A language without a region keeps the visitor's own conventions: `<html lang="en">` still shows an Australian visitor 15 Jan 2024, and only `lang="en-US"` asks for Jan 15. The picker documents `lang` as an attribute; changing it on the picker re-renders. A required date-and-time field now says "Please choose a date and time." rather than "a date."
- An enhancement's `defaults` is one object rather than a getter that handed back a fresh copy each time, so `Toggle.defaults.openClass = 'is-open'` now changes every toggle mounted from then on where before it changed a copy nothing read and nothing reported. All thirteen enhancements did this. A test now holds every component to `Component.defaults === Component.defaults`, and the published types say `static defaults: {…}` rather than a getter a TypeScript page could not assign to. A page that reads `getStats().defaults` from Toggle or Tabs gets the live object now.
  : every property a component's own stylesheet reads must be documented, and every documented property must be read by something. `<p-modal>` documented 14 of the 51 it read and nothing failed, which is how that gap lasted. The dozen values `<p-modal>` and `<p-datetime>` use only to stay consistent with themselves are named in the test as deliberately internal, so excluding them is a decision on the record rather than an omission.

## [0.7.7] - 2026-09-17

### Added

- Each element's documentation page says what its markup does before the module loads, under _Without JavaScript_, and what to render on the server where that matters — a `<select>` in place of a `<p-select>`, an `<input type="file">` in place of a `<p-uploader>`. The enhancement components have always answered this question on their pages; the five elements never did. The answer lives on the component contract as a `withoutJs` field, so a new element cannot quietly ship without one.
- The way to use an enhancement without the framework is written down. Every enhancement but `Accordion` and `SelectLoader` has had a static `enhanceAll()` for some time, and it appeared in the published type declarations and nowhere else, so the first question a reader asks — whether using one component means adopting a framework — could only be answered by reading the source. It is now on each enhancement's page, in Getting started, and in the README.
- `<p-datetime>` exposes twelve shadow parts, where it had none: the field, each value button, the calendar trigger, the panel, the month navigation and its month button, the day grid, each day, each time select, the AM/PM select, and the action buttons. Making the days circular, or the Apply button match a site's own, needed a fork of the component before this; `<p-modal>` had six parts and `<p-select>` three, so this was the one element a page could reach the outside of and nothing within.
- The two components with the most to style say what can be styled. `<p-modal>` documented 14 of its custom properties and now documents 45, `<p-datetime>` 13 and now 45. Each entry names the design-system token it follows, so setting `--button-primary-bg` once to change every component, or `--modal-btn-primary-bg` to change modals alone, is readable from the component's own page. The properties a component uses only to stay consistent with itself, such as its spacing and font scales, are deliberately left out: listing them would bury the ones worth setting.
- `<p-uploader>` documents what its endpoints must answer, not only what they receive. The upload endpoint has always had to return JSON carrying an `id`, which becomes the file's `file-id` and is what every later update, delete and sequence request names; without it an upload appears to work and nothing that follows can refer to the file. The optional `preview` and the rules for reading a failed response are written down with it.
- DataTable takes `data-datatable-sort-status`, `data-datatable-sort-ascending` and `data-datatable-sort-descending`, so the sort in its status line is translatable like the rest of its text.

### Changed

- **Breaking:** the tinted grounds behind a status message are named `--color-danger-tint`, `--color-success-tint` and `--color-warning-tint`, not `-bg`. A status colour has two grounds -- the solid colour a button is filled with, and the tint a message sits on -- and naming one of them `-bg` said which CSS property it happened to be set on rather than which of the two it is, so `--color-danger` and `--color-danger-bg` read as two backgrounds without saying how they differ. `-tint` names the role, and stays true in both themes: the value is a pale red in the light theme and a translucent one in the dark. Only `--color-danger-tint` was read by anything, by `<p-uploader>` and Lazysrc; the other two were read by nothing.
- **Breaking:** `<p-uploader>`'s custom properties are named `--uploader-*` rather than `--puploader-*`. Every other component names its properties after the thing rather than the tag -- `--modal-*`, `--datetime-*`, `--select-*`, `--toast-*` -- and the uploader was the single exception, on the component with the most surface to style. Its own contract already mixed both prefixes. A page that sets any of `--uploader-radius`, `-border-width`, `-border-color`, `-bg`, `-color`, `-shadow`, `-padding` or `-files-gap` under the old name needs the prefix changed; nothing else moves, and the two `--uploader-file-*` properties were already correct.
- The design system page is a tour of the tokens rather than a gallery of components. It showed every component twice, once light and once dark, with token controls beside them: that proves what a value does when you drag it and never says what it is for, and it repeated what each component's own page already shows. It reads as four layers now, and within them 31 rows, one per family rather than one per token -- a lone swatch for `--color-accent-contrast` demonstrates nothing, while `--color-accent` beside its hover and its contrast demonstrates a button. A status colour appears twice, as the solid carrying its contrast text and as the tint carrying its strong text, which is the only way to see that those two are not interchangeable. Each layer says what it is for and which one to reach for first. Values are editable where they are shown: a colour picker on a literal colour, a slider on a length, and one press to copy any of them through the library's own `CopyToClipboard`. A token declared as `var(--something-else)` gets neither and says what it follows instead, because replacing a reference with a literal cuts it out of the layer it was following. Every token the design system declares is there, read from the stylesheets rather than from a list: the page offered 90 of 158 and nothing failed, so `--color-text`, which five components read, was missing along with almost every button, field, panel and modal value. Each token also names the components that read it, counted from the stylesheets, and twenty of them say that nothing reads them at all.
- A page can set its brand colour once. `--color-accent` now reads `var(--brand-primary, ...)`, with `--brand-primary-hover` and `--brand-primary-contrast` beside it, in the light theme and the dark one. `--brand-primary` existed before as a hook referenced in exactly one place and declared nowhere, so it did nothing; it is now the entry point, and `--color-accent` is the mechanical role every component reads. Nothing changes for a page that does not set it.
- A dropdown surface follows the panel surface for everything the two had identical -- border width and colour, background, text and shadow -- and keeps its own radius and its three item-state colours, which are the parts that genuinely differ. Changing a panel now changes dropdowns with it, where before five values happened to agree and would silently drift apart. The resolved values are unchanged.
- The documentation site's navigation is a drawer on a screen narrower than 56rem, instead of a full screen of links above every page's heading. It is built from the site's own Toggle, so it closes on an outside click, on Escape and when a link in it is followed, and it slides in over the page rather than pushing it down. A close button sits at the top of the panel and stays there while the list scrolls; it is a second trigger for the same panel rather than anything new. Every rule waits for the attribute Toggle writes when it mounts, so before that — and on a page with scripting turned off — the navigation is the plain list it has always been and no trigger is shown.
- `llms-full.txt` carries a component's whole reference. It listed attributes, events and CSS properties, while the pages list seven tables, so the properties, methods, slots and shadow parts were absent — an agent reading it was told what it could set and never what it could call. It also stopped at a component's first example; it now carries all of them. Both files name the version they describe, and the Custom Elements Manifest link is pinned to that version rather than always naming the newest release. The manifest is served by the documentation site as well, when the package has been built.
- DataTable's default status message ends with `{sort}`, so it reads "Showing 1–10 of 40 rows, sorted by Name, ascending". A status message set through the attribute is unchanged, and one that leaves `{sort}` out keeps working exactly as before.
- A documentation page swapped in by the router fades and lifts into place, 0.44s for the pair, and the reading column is the only part that moves: the sidebar's only change is which link is marked current, which is not worth animating. The timing lives in the site's stylesheet rather than in the configuration, because the fragment swapper waits for whatever animation the class it adds starts and uses its own duration only as a fallback. A visitor who prefers reduced motion gets no animation and no wait for one.
- The heading of a page the router has just swapped in no longer draws a focus ring when the navigation came from a click. The router gives it `tabindex="-1"` and focuses it so a screen reader lands on the content instead of the top of the document, and `trackFocusSource()` already records which input method was last used, so the ring now appears for a keyboard navigation and not for a pointer one.
- Getting started says what a bundle that never runs looks like, separately from a loader that fails. Nothing is marked, nothing is emitted, and the stylesheets that hide content until a component mounts keep hiding it, which is a different thing to debug and was described only as a component that was never registered.
- The home page says the router is a choice. Its only quickstart switched the router on without mentioning it, and the page closed by promising that links swap in place -- to a reader who came looking for a library rather than a framework, that reads as the point of the thing rather than an option. The quickstart no longer passes `router: {}`, the sentence that follows says what adding it does and that leaving it out keeps every link an ordinary link, and a clause above the component grid says what separates an enhancement from a web component, which the grid has always labelled and never explained.
- A component page's reference tables run under both columns instead of inside the reading one. They had about 600px for tables that want 650, so descriptions clipped mid-word and the type column broke inside its own values; this was a regression from the two-column layout, and worse than I judged when I shipped it. Code samples that scroll now show a thin scrollbar, so a clipped sample says that it continues.
- The deprecation window is stated in wall-clock time as well as releases: at least one minor release and thirty days, whichever is longer. A window measured only in releases means very little when 0.5.0 to 0.6.0 took six hours.
- The package can be loaded from a CDN with no build step, and Getting started says so, with the request waterfall named honestly rather than left to be discovered. `unpkg` and `jsdelivr` fields point at the module entry.
- Coverage measures the whole suite. `npm run coverage` ran the unit project alone, which is the half that does not cover `<p-select>`, `<p-datetime>` or `<p-uploader>`, and reported about 51% with the gate set below that. It now runs both projects through `vitest.coverage.config.js` -- against chromium alone, because the coverage provider will not instrument the three browsers the test run uses -- and reports 83.79% of statements and 74.23% of branches, with the gate re-baselined to match.

### Fixed

- Tabs no longer hides a page's own panels for good when it cannot use their markup. The shipped stylesheet shows one panel until `data-tabs-enhanced` appears, and Tabs gave up without writing it when a tab list, a panel container, or any tabs or panels were missing — so the cheapest markup mistake removed content from the page and nothing put it back. Tabs now writes the attribute either way, `true` when it mounted and `false` when it could not, and `data-tabs-list` and `data-tabs-panels` are marked required in the documentation.
- A `<p-select>` given a `value` before its remote options arrive shows the matching label rather than the bare value. Options from `data-select-src` replaced the list without resolving the value against it, so an edit form redisplaying a saved row showed its id — `r5` instead of `Row 5` — until someone opened the list and chose again. The label resolves once the rows land, and only for a fetch of the empty query, so a search in progress keeps what the visitor typed.
- The package's own elements no longer put their contents into the page before the module that defines them arrives. A custom element is inert markup until it upgrades, so a `<p-modal>`'s title, body and buttons sat in the flow as ordinary elements for as long as the module took to load. The framework stylesheet now hides the five tags until they are defined — but only where scripts are running: with scripting off the module is never coming, and hiding content nothing will bring back is worse than showing it unstyled.
- A closing Toggle target is taken out of the tab order while it animates away. The trigger reports `aria-expanded="false"` as soon as it is clicked, while the panel stays on the page for the length of its animation, so everything focusable inside it was reachable from a state the page had already called shut. It is marked `inert` for exactly that window: once closed, `hidden` has it, and a page that overrides `hidden` to show the target anyway — a sidebar that is a drawer on a phone and a column on a desktop — gets a target it can still use.
- DataTable says what a sort changed. Its status is a live region, and sorting changes the order of the rows without changing how many are showing, so the sentence was identical before and after and a screen reader announced nothing at all.
- The Lightbox counter names the image it moved to. It was the only live region in the component, so "2 / 3" was everything a screen reader was told about a picture it could not see. The name is read out with the count and is not shown: the badge still reads 2 / 3.
- A `<p-select>` can be cleared without a pointer. Choosing a value makes the input read-only, and the button that clears it is hidden until the list is open and was never in the tab order, so a keyboard could reach a value and then never change it — worst with `data-select-src`, where the list holds the previous query's first page, so the options still reachable were the wrong ones. Backspace or Delete now clears the value and returns the input to searching, running the same search an emptied input would.
- The documentation site no longer scrolls sideways on a phone. An example's tab strip is wider than a narrow screen and had nowhere to put the overflow, so it moved the whole page across and cut off the left margin. The strip scrolls inside its own box.

## [0.6.0] - 2026-09-15

0.6.0 removes everything 0.5 deprecated. The [upgrade guide](https://dev.parallelogram.com.au/upgrading.html) lists each change and what to use instead.

### Changed

- `Parallelogram` loads `RouterManager` with a dynamic `import()`, and only when `router` options are given, so pages without the router don't download its code. The promise `run()` returns resolves once the router has loaded and started, with `app.router` set. After calling `init()` directly, `app.router` is `null` until then, `router:initialized` is emitted when it starts, and links followed in the meantime load pages normally. Components that mounted before it loaded are given the router. `RouterManager` is still exported from the package root.
- `PageManager` no longer subscribes to router events or mounts components in its constructor. Call the new `pageManager.start()` after creating it. A second call does nothing, a destroyed manager can't be started again, and `destroy()` works whether or not it started. `Parallelogram` calls `start()` for you.
- `setState()` writes state only to `data-<component>-state`, and `getElementState()` reads only that attribute.
- `<p-datetime>` stores, submits and reports local date and time strings like the native inputs: `yyyy-mm-ddThh:mm` in datetime mode and `hh:mm` in time mode, with seconds only when they aren't zero, instead of UTC instants such as `2024-01-15T03:30:00.000Z`. Values, `min`, `max` and linked fields given as ISO instants are still read, as the local date and time they stand for. `format` still decides what is submitted.
- Focus rings show only after keyboard use. `Parallelogram`, `<p-select>`, `<p-datetime>` and `<p-uploader>` record whether the last input was a keyboard or a pointer as `data-focus-source` on `<html>`, and on those elements while they have focus, and the framework styles hide focus outlines and form field focus rings after pointer input; fields keep their focused border colour. Browsers show a ring in a clicked text field under `:focus-visible` alone, which is why the attribute is needed. Without the script, rings show as before.

### Removed

- The `@parallelogram-js/core/dev/components/*`, `dev/core/*` and `dev/adapters/*` import paths. Use the normal paths; bundlers that resolve the `development` export condition pick the development build.
- The state copies in `data-<component>`, in `data-toggle-target` on Toggle targets and in `data-modal` on `<p-modal>`. Read `data-<component>-state`, `data-toggle-state` and `data-modal-state`.
- The `modal:open`, `modal:close`, `toast:show` and `toast:close` events. Listen for `p-modal:open`, `p-modal:close`, `p-toasts:show` and `p-toasts:close`.
- The `upload:success`, `upload:error`, `sequence:update`, `file:update` and `file:delete` events. Listen for the `p-uploader:*` and `p-uploader-file:*` events.
- FormEnhancer's `data-form-validator`, `data-validate` and `data-validate-message`, and the `form-validator:mounted`, `form-validator:submit-blocked` and `form-validator:submit-valid` events. Use `data-form-enhancer`, native validation attributes, `data-form-enhancer-message` and the `form-enhancer:*` events.
- CopyToClipboard's `data-copy-target` and `data-copy-text`. Use `data-copytoclipboard-target` and `data-copytoclipboard-text`.
- Lightbox's `data-lightbox-state-closed-class`, which was never applied. Listen for `lightbox:closed`.
- `<p-datetime>`'s `isRange` property. Use `range`.
- `core/ComponentStates` with `ComponentStates` and `ExtendedStates`. Use plain strings such as `'open'` and `'loading'`.
- BaseComponent's deprecated `_elementsKeys()` and `_getDataAttr()`, and the unused `_camelCase()`, `_waitForTransition()` and `_createElement()`. Use `trackedElements()`, `getAttr()`, `getBoolAttr()` and `getNumberAttr()`.
- ComponentRegistry's unused `validate()`, `detectCycles()`, `toPascalCase()` and `fork()`. Use `ComponentRegistry.create()` instead of `fork()`.
- The legacy design-system variables module (`design-system/variables`), with names such as `$spacing-*`, `$font-size-*`, `$transition-*`, `$legacy-color-*` and `$size-*`, and the unused `$color-focus-shadow` token. Use the tokens from `design-system`.
- The `legacy` option of the internal `dispatchComponentEvent()`.

### Fixed

- `<p-datetime>` no longer closes in Safari when the next or previous month arrow, the month and year heading, or the space between days is clicked. Safari doesn't focus a clicked button, so focus moved to the nearest focusable element around the picker, such as a `main` with `tabindex="-1"`, and the picker took that as focus leaving it. The panel now takes focus itself.

Date-only values are now read as local dates in every mode, and ISO instants given in date mode still work. Datetime and time modes keep ISO instants.

- **Behaviour change:** `p-modal` is built on a native `<dialog>` opened with `showModal()`. Focus returns to the element that opened it, however it was opened, once no other modal is still open. The close button is hidden when the modal can't be closed.

- **Behaviour change:** Lightbox shows images in a native `<dialog>` named "Image viewer" and opened with `showModal()`. Real sources in the markup are now left alone, so such images also work without JavaScript, and `loading="lazy"` and `decoding="async"` are added when missing. Sources in `data-lazysrc-src`, `data-lazysrc-srcset` and `data-lazysrc-sizes` (and on `<source>` elements) are copied across as soon as the image mounts, so the browser decides when they load. `data-lazysrc-threshold` and `data-lazysrc-root-margin` now apply only to `data-lazysrc-bg` background images, which start loading 600px from the viewport by default. `lazysrc:forceLoad` and `loadElement()` switch an image to `loading="eager"`, and `loadElement()` resolves once the element has loaded or failed.

The old `loading`, `loaded` and `error` defaults clashed with site styles and never matched the shipped stylesheet, which now styles `data-lazysrc-state` instead. The fade is now a CSS transition that only runs for users who haven't asked for less motion, `lazysrc:loaded` fires once per image, and `data-lazysrc-fade-duration` sets `--lazy-transition-duration`. Failed images get an outline instead of a border so the layout doesn't shift. Images are decoded before they count as loaded, `data-lazysrc-fetchpriority` sets `fetchpriority`, `loadTime` in `lazysrc:loaded` comes from Resource Timing, and background images with the same root margin and threshold share one IntersectionObserver.
- **BREAKING:** FormEnhancer is rebuilt on the browser's constraint validation. It re-implemented the native rules with its own checks, so empty optional fields failed (`data-validate="url"` ran `new URL('')`), checkboxes always passed `required`, and patterns containing `|` or `:` broke. The form wasn't marked `novalidate`, so the browser's own validation ran first and showed a second error UI. Fields now declare native attributes (`required`, `type`, `minlength`, `min`, `max`, `pattern`), which also work without JavaScript. FormEnhancer sets `novalidate` while mounted and shows the browser's localised `validationMessage`, or the field's `data-form-enhancer-message` or per-constraint `data-form-enhancer-message-<constraint>` text.

Errors are now found inside their own form (or created after the field), linked with `aria-describedby`, marked with `aria-invalid`, kept visible while the user corrects the field and cleared once it is valid. A blocked submission focuses the first invalid field, a radio group reports one error, `reset` clears errors, listeners are removed on unmount, and fields added after mounting are validated. The `errorClass` and `validClass` options were never read, so fields got a literal `undefined` class; they now default to `is-invalid` and `is-valid` and are set with `data-form-enhancer-error-class` and `data-form-enhancer-valid-class`.
- **BREAKING:** Toggles are independent unless they share a `data-toggle-group`. Opening any toggle closed every other toggle on the page, so opening a menu collapsed an unrelated FAQ answer. Because `data-toggle-close-navigation` defaulted to on, every toggle also closed on any outside click, with or without `data-toggle-capture`. Outside clicks now close only capture toggles, which also close when focus moves outside them, and opening a toggle closes only the others in its group. The `multiple` option is gone; give toggles that should close each other a shared `data-toggle-group`.

Escape closed every open toggle wherever focus was, including when it was meant for a dialog, and left focus on hidden content. It now closes only the toggle that holds focus, returns focus to its trigger and ignores an Escape another component has already handled. One set of document listeners replaces a keydown listener per trigger, `aria-controls` names the target's id (giving the target one if needed) instead of the selector text, and `data-toggle-close-escape="false"` turns Escape off.
- Toggle finished opening and closing on a fixed 750ms timer that ignored `--toggle-transition-duration`, and toggling quickly let a stale timer reopen a closed target. It now waits for the target's animations, a newer change cancels an older one, and the state changes at once under reduced motion. The stylesheet animates opacity and transform instead of `max-height` up to `100vh`, which clipped tall content, and its keyframes are renamed `toggle-open` and `toggle-close`. `toggle:show` and `toggle:hide` reached the event bus twice; they are now emitted once, with a `timestamp`.
- **Behaviour change:** Tabs hides inactive panels with the `hidden` attribute instead of inline `display: none`. While scripts are enabled but Tabs hasn't loaded, the shipped stylesheet shows only the first panel, so pages no longer show every panel and then collapse. Without JavaScript every panel stays visible, and tabs can be in-page links to their panels. The JSDoc no longer tells authors to hide panels with inline styles, which left them unreachable without JavaScript.
- Choosing tabs in quick succession could leave two panels visible, because Tabs waited on timers before recording the active tab. The selection and panels now change at once, and the new panel fades in through CSS (skipped under reduced motion), marked `entering` until its animation ends. Unmounting left roles, `tabindex`, `aria-selected` and hidden panels behind; Tabs now puts the markup back as it was. `tabs:change` reached the event bus twice; it is now emitted once, with a `timestamp`.
- **Behaviour change:** tabs.scss styles `[data-tabs-list]`, `[data-tab]` and `[data-tab-panel]` instead of `.tabs__list`, `.tabs__tab` and `.tabs__panel`, which Tabs never added. The selected tab's text contrast rises from about 2.6:1 to 5.6:1, tabs get a `:focus-visible` outline, colours come from `--tabs-*` custom properties, and `transition: all` is replaced by explicit properties.
- The main stylesheet (`@parallelogram-js/core/styles`) left out Toggle, Tabs and Scrollreveal, so sites that imported it got toggle targets that never hid. It now includes them. To let your own styles win over the framework's whatever their specificity, import it into a cascade layer, for example `@import url('…/index.min.css') layer(parallelogram);`.
- **Behaviour change:** reveal.scss hid every `[data-reveal]` element with CSS alone, so content stayed invisible when JavaScript didn't run or failed to load. It now hides content only while scripts are enabled and Scrollreveal hasn't loaded, then follows `data-reveal-state`, animates only for users who haven't asked for less motion, and shows everything under reduced motion.
- Web components broke on pages with a strict Content Security Policy or Trusted Types. Their styles were inline `<style>` elements, which `style-src` blocks, so a closed `p-modal` rendered its content on the page, and their templates were assigned to `innerHTML`, which throws when Trusted Types are enforced. Each component now adopts one shared constructable stylesheet, parsed once for all instances, and static templates go through a Trusted Types policy named `parallelogram`, which a page enforcing Trusted Types must allow with `trusted-types parallelogram`. Lightbox's icons and DataTable's row clearing no longer assign HTML strings either.
- **Behaviour change:** every web component's stylesheet carried a ~5 KB `:root` block of design-system tokens, which can't match inside a shadow tree, and the components used those tokens without fallbacks. Without the framework stylesheet, `p-select` menus and `p-modal` panels had transparent backgrounds and toasts and uploaders lost their rounded corners. The tokens now live in `design-system/_root.scss`, which the main stylesheet includes, and every component falls back to the default values, so the components render on their own and still pick up token overrides set on the page. Sass that relied on `@use 'design-system'` to output the tokens should `@use 'design-system/root'` instead.
- Focus indicators were missing or nearly invisible. `p-select` removed its input outline and showed nothing in its place, DataTable's search box and `p-datetime`'s time selects used a 10%-opacity ring (about 1.1:1 against white), and the design-system `focus-visible` and `button-reset` mixins removed outlines. They now show a 2px solid outline. The form-control focus ring keeps a transparent outline so it survives forced colours, and `p-select` options, `p-datetime` dates and the selected tab are marked with system colours when forced colours are active.
- **Behaviour change:** `p-toasts` announces through two live regions that exist from the moment it is created, polite for info and success and assertive for warnings and errors, instead of a role on every toast nested inside an unnamed live region. The first message and repeated messages are now announced. Error toasts stay until dismissed unless you pass `timeout`, and every timer waits while the pointer or keyboard focus is on the toasts.
- `p-toasts` accepts `title`, `dismissible: false` and `duration` (an alias for `timeout`), which Toast.js passed and it ignored, and `danger` as an alias for `error`. The dismiss button is a 24px target, the leave animation (which referred to missing keyframes) plays and respects reduced motion, the documented `top-center` and `bottom-center` placements work, toasts no longer shrink below their minimum width, and the stack, toasts, titles and dismiss buttons are exposed as parts.

- The global toasts stylesheet repeated `p-toasts`' positioning, which overrode its `placement`, and declared `--toast-*` tokens that nothing read. It now only declares the tokens, and `p-toasts` reads all of them. `--toast-bg-warn` is renamed `--toast-bg-warning`; the old name still works.
- **Behaviour change:** the Toast component is now a small bridge to AlertManager. It called a `window.alertManager.show` that doesn't exist, passed `duration`, `title` and `dismissible` to a `p-toasts` API that ignored them, and fell back to a blocking `alert()` when the page had no `p-toasts`. Clicking a trigger now shows its toast through AlertManager, which creates a `p-toasts` when needed. Attributes are read on each click, `data-toast-title` works, and `alert()` is never called. `toast:shown` reaches the event bus once instead of alongside a second `toast:show`, and trigger listeners are removed on unmount.
- **Behaviour change:** `AlertManager.error()` toasts stay until dismissed instead of closing after 6 seconds. AlertManager no longer overrides the `placement` of a `p-toasts` already on the page, and finds a new `p-toasts` when the one it used has been removed, for example by a page swap.
- **Behaviour change:** `p-select` follows the WAI-ARIA combobox pattern. The combobox role, `aria-expanded` and `aria-controls` were on a wrapper while focus sat on an unnamed input, and options had no ids, so screen readers never heard the highlighted option. The input now carries the role and `aria-activedescendant`, is named after the host's `aria-label` or its `<label for>` (without a trailing colon), and receives focus passed to the host. The list is no longer a Tab stop while it animates closed. Moving the highlight no longer rebuilds the list and keeps the option scrolled into view. Home and End jump to the ends of the list, Tab chooses the highlighted option, Escape puts the chosen label back, and the list closes when focus leaves, replacing a document click listener that was never removed. The list no longer opens when the input receives focus (set `data-select-open-on-focus` to keep that) or on Enter while closed, so Enter submits the form. The highlighted option is marked `data-active` instead of `aria-current`.
- `p-select` flattened `<optgroup>`s, read its `data-select-*` attributes only when created, ignored options added later, and appended a live region to `document.body` on every connect. Groups now render as labelled groups, attributes and options are picked up whenever they change, native `input` and `change` events are dispatched alongside `p-select:change`, and the number of matches is announced from a live region inside its shadow root. Loading `p-select` no longer loads `p-toasts` and AlertManager too.
- `p-select`'s documented `data-select-src` search was a stub that never fetched anything. It now requests the URL with `{q}` replaced by the typed text once `data-select-min` characters have been typed and `data-select-debounce` milliseconds have passed, cancels outdated requests, sets `aria-busy` on the list while loading and announces errors. The response must be JSON: an array of `{ value, label, disabled?, group? }`, or an object with those in `options`.
- **Behaviour change:** DataTable's sortable headers get a `<button>`, and the sorted header gets `aria-sort`, so keyboard and screen-reader users can sort; they were click-only `<th>`s that announced an arrow glyph. Pagination is a `<nav aria-label="Table pagination">` of `type="button"` buttons (they used to submit a surrounding form), with `aria-current="page"`, labelled Previous and Next buttons and a window of page numbers instead of one button per page, and focus stays on the pressed control. A status message announces which rows are showing after sorting, filtering or paging. The search box is `type="search"` and its label is linked to it (it produced an `htmlfor` attribute), and the label, placeholder and empty-row text are configurable.

Rows are moved instead of cloned, so their listeners and form state survive.
- DataTable's `loadData()` applied overlapping requests in the order they arrived, left the previous sort arrows showing, and wrote its error message to an attribute the stylesheet didn't read, leaving an empty red box. A newer load now cancels an older one, the sort resets, `aria-busy` is set while loading, and errors and empty results appear as rows in the table, errors with `role="alert"`. `datatable:loaded` and `datatable:error` reach the event bus once, `datatable:mounted` and `datatable:rendered` are also DOM events, the `sortIcons` constructor option is honoured, listeners are removed on unmount, and unmounting removes the search box, status and pagination and puts the headers and rows back.
- datatable.scss uses low-specificity `:where()` selectors and `--datatable-*` custom properties, gives the current page 4.5:1 contrast, adds forced-colours and reduced-motion rules, and no longer stops header text being selected.
- SelectLoader built its empty and error messages as HTML from `data-selectloader-empty-message` and the error text, and its Retry button found its select by scanning every `<select>` on the page. Messages are now plain text and Retry reloads its own select. A JSON response is reported as an error instead of rendering "[object Object]", loaded content and errors are announced, transitions are skipped under reduced motion, and a slide no longer leaves inline styles on the target, including a zero height that hid error messages. The JSDoc now says fragments must be trusted, same-origin HTML.

It saves only the fields that changed (still one `update-action` request per field) and shows a message in the dialog if a save fails. The per-field edit panels, their `edit-<key>` panel names and the per-field edit buttons are gone. The filename is a paragraph instead of an `<h1>`, and the delete confirmation is a group instead of an unmanaged `role="dialog"`.
- Hidden panels in `p-uploader-file` (such as the delete confirmation) stayed in the tab order and the accessibility tree while out of view. Panels that aren't showing are now `inert`.
- **BREAKING:** `p-uploader` no longer falls back to `/upload`, `/update`, `/delete` and `/sequence` when its action attributes are missing, so a misconfigured uploader could send deletes to a route nobody set up. Files can only be added with `upload-action`, and editing, deleting and reordering are only offered when `update-action`, `delete-action` and `sequence-action` are set. The `window.MockXHR` fallback is gone; use `setXHR()`.
- `p-uploader` could not be used from the keyboard: the only way to add files was a label for a hidden input. It now has a focusable Add files button. When full it hides its drop zone, and files over the limit, of the wrong type (`accept-types`) or too large (`max-file-size`) are reported in the component instead of through `alert()`, or not at all before; previously `accept-types` only filtered the file picker and `max-file-size` was ignored.
- `p-uploader` sent every file under `file`, ignoring `input-name`, treated any status other than 200 (such as 201 Created) as a failed upload, and kept uploads and saves running after it was removed from the page. It now uses `input-name` (default `file`), accepts any 2xx response, and cancels requests on disconnect.
- A failed reorder save removed every file from `p-uploader`, and a drag that ended outside the uploader (or was cancelled) left the files reordered without saving. The previous order is now restored with a message when the save fails or the drag is abandoned.
- A `p-datetime` that was moved or re-added to the page would not open, because every connect added another set of listeners, and each connect leaked a document click listener. Importing a second copy of the component threw because `p-datetime` was defined again.
- **Behaviour change:** `p-datetime` opens on the month of the value being edited instead of the current month.
- **Behaviour change:** in range mode, picking a start date (or an end date before the start) begins the range there and asks for the end next, keeping an end that still follows it. Picking again in a complete range used to replace its end and swap the ends around. Clear now empties both ends.
- Fragments in a target group were replaced one after another, and components, the page title, scroll position and focus were only updated once every fragment's in-transition had finished. Fragments are now replaced independently, so a slow or failing one no longer holds up the rest, and each fragment's components mount as soon as its content is swapped.
- TransitionManager's class animations never removed their class, so repeating one never restarted it, and waited forever for an `animationend` that a class without an animation never fires. Classes are now removed when their animation ends, a class that does not animate finishes at once, a new transition cancels the one running on the same element, and the JavaScript animation uses the Web Animations API. `p-select` could end up with a hidden listbox and `aria-expanded="true"` when reopened while its close animation was running.
- Fragment transitions set through `targetGroupTransitions` waited for an `animationend` or `transitionend` event that never fired when the class defined no animation or the fragment was hidden, so the swap never finished and the page title, component mounting and later navigations never happened (as in the demo's navbar). Transitions now wait for the fragment's running animations, finish straight away when there are none, and give up shortly after the longest animation should have ended.
- **Behaviour change:** after a client-side navigation, keyboard focus fell back to `<body>` (the activated link was usually swapped out) and screen readers heard nothing, unlike a full page load. PageManager now moves focus, without scrolling, to the element named by the URL hash, an `[autofocus]` element, or the new main fragment's first `h1` (falling back to the fragment itself, given `tabindex="-1"` when needed), and announces the new `document.title` through a shared polite live region.
- **Behaviour change:** Back and Forward landed at the top of the page (or scrolled the old content before it was replaced). While the router runs it sets `history.scrollRestoration` to `manual`, remembers the scroll position of each history entry, restores it once the page is replaced, and saves it into `history.state` so it also survives a reload. Moves between hash entries of the same page restore their position too.
- Back and Forward always replaced the `main` target group, even for entries created by a `data-view-target` link. They now replace the fragment changed by the navigation being undone or redone.
- Links to another page with a hash (`/pricing#plans`) landed at the top of the new page. The target is now scrolled into view and focused after the swap.
- After a server redirect, the address bar and `router.currentUrl` show the URL the page came from instead of the one that was requested.
- `router.isNavigating()` threw a TypeError, because a boolean property of the same name hid the method.
- `router.get()` cancelled any navigation in progress and was cancelled by the next one, so SelectLoader loads and page navigations aborted each other and showed error messages. Requests made with `router.get()` are now independent, and a `signal` passed to it no longer disables the timeout. Timeouts reject with a `TimeoutError` instead of an `AbortError`.
- **Behaviour change:** the router handles link clicks with one listener on the document, so links added by components or scripts after startup are routed too. It ignores clicks that another handler has cancelled or that use a mouse button other than the main one, respects `data-router-skip` on any ancestor, and leaves `rel="external"` links and cross-origin links to the browser (`data-router-enhance` now only overrides the file extension check).
- **Behaviour change:** the router no longer intercepts same-page `#hash` links, which scrolled without moving focus, never applied `:target` and ignored reduced motion. Use `scroll-behavior: smooth` inside `@media (prefers-reduced-motion: no-preference)` for smooth scrolling. Back and Forward between entries that differ only by hash no longer re-fetch the page.
- **Behaviour change:** SelectLoader shows the most recent choice when an earlier one is still loading, instead of ignoring the new choice. It marks the target `aria-busy` instead of disabling the select, clears its error class after a successful load, and cancels a pending load when the choice is cleared or the component is unmounted.

### Changed

- `<p-modal>` with `data-modal-closable="false"` still closes from its own `data-modal-close` buttons, so a confirmation that must be answered can be answered. It ignores only Escape, the backdrop and its close button; in 0.4 those buttons did nothing and only script could close the modal.
- The README starts from `Parallelogram.create()`, states the Baseline 2023 browser floor, and lists every component in tables generated from the contracts by `npm run readme`, which a unit test keeps current.
- Router history entries store `key`, `position`, `viewTarget` and `scroll` in `history.state`, and the router adds a `key` and `position` to entries it did not create (the first page and native hash navigations).
- Fragment swapping moved out of PageManager into `FragmentSwapper` (`@parallelogram-js/core/core/FragmentSwapper`), which can also be used on its own. PageManager loads it when a router is present or on the first `replaceFragments()` call, so pages without a router no longer download the swapping, head and transition code. A PageManager destroyed while a navigation is under way no longer changes the page afterwards.
- The library builds as one production and one development Rollup graph. Code shared between entries (BaseComponent, DOM helpers, state helpers) lives once in `dist/shared/` instead of being copied into every component bundle.

- Web component SCSS is now compiled by a local Rollup plugin (`rollup-plugin-scss.js`) using Sass's modern API and cssnano 9, replacing the unmaintained `rollup-plugin-postcss`. Minified CSS now keeps declarations in source order, and inline SVGs keep the `viewBox` from source (cssnano 5 stripped it).
- Updated dev dependencies and removed unused ones (`@rollup/plugin-replace`, `babel-plugin-transform-remove-console`, `postcss-cli`, `postcss-import`).
- Development now requires Node `^22.22.3`, `^24.15.0` or `>=26`, enforced through `devEngines`.
- The demo build deletes stale hashed chunks from `demo/dist`.

## Migration from @peptolab/parallelogram

If migrating from the old package:

1. Update package.json:

   ```diff
   - "@peptolab/parallelogram": "^1.2.9"
   + "@parallelogram-js/core": "^0.1.0"
   ```

2. Update all imports:

   ```diff
   - import { ComponentRegistry } from '@peptolab/parallelogram';
   + import { ComponentRegistry } from '@parallelogram-js/core';

   - import '@peptolab/parallelogram/components/PModal.js';
   + import '@parallelogram-js/core/components/PModal.js';
   ```

3. Run:
   ```bash
   npm uninstall @peptolab/parallelogram
   npm install @parallelogram-js/core
   ```
